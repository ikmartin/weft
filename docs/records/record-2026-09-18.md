# 2026-09-18 — M1 to M4, and the first closed neighbourhood

M1 of [plan 0.1](../plan-0.1-weft.md) is built and run on all three corpora. The crawl is ported from loom (`refs/crawl/*`, `refs/identity.py`, `refs/resolve.py`, `scan/bib.py`, the download helpers of `digest/fetch.py`) and refactored: settings instead of a quilt, seeds instead of a bibliography, binding instead of candidates, one rate budget per host, and an offline transport so no test touches the network.

## What is built

`weft init`, `weft crawl plan|fetch|status`, `weft survey`, `weft index rebuild|counts`, `weft bib`. The work/version/result model with URI-shaped keys (`arxiv:1709.09864v3#thm-4.1`), files under `works/` as the truth, a SQLite index behind one `Store` interface, and `rebuild` replaying the files into it. 123 tests, one of them network-marked and skipped by default; ruff and mypy clean.

## Measurements

**relloc — a real bibliography.** 22 entries became **20 works**: 15 with arXiv sources, 5 metadata-only, **3 bound by lookup, 2 unidentified (10%)**. loom, on the same bibliography, reports 3 works unresolved of 22 entries (23%) because it records candidates and refuses to bind; weft binds a strong match, which is the difference.

**ACGS — one work to depth 2.** The seed declares its arXiv id, and zbMATH gave its journal DOI, which became the work's key while its home stayed `arxiv/1709.09864`. The survey took **2 minutes** and found **48 cited works**. The plan at depth 2 found **45 works: 38 downloadable (35 arXiv, 3 open copies), 7 metadata-only, 4 excluded, 36 bound by lookup, 2 unidentified**, from 38 lookups.

**The survey reproduces loom's argument against a default subject filter.** By primary MSC family the cited works are `14N 10 · 14H 8 · 14T 4 · 14- 4 · 14F 3 · 14A 3 · 14D 3 …`; by *any* of their codes `14N 19 · 14H 18 · 14D 16 · 14A 14 · 14T 11 …`. A default taken from the seeds' primary codes would have dropped most of what the seed actually leans on.

## Findings

**A subject filter silently drops what nothing classified.** All 4 of ACGS's excluded references were excluded for having neither an MSC code nor an arXiv category: `arxiv:1301.4748` (Holomorphic curves in exploded manifolds), `arxiv:1703.05433` (Tropical gluing formulae for Gromov-Witten invariants), `arxiv:math/9907124` (a withdrawn paper on log modifications) and `doi:10.7301/z0hq3x99` (Ulirsch's thesis). Two are plainly in the seed's own subject. The filter was not judging them; it had nothing to judge them by. A later rule should keep an unclassified work that something cites more than once, or list it in the plan for a decision rather than dropping it.

**One work reached twice by different routes can be both identified and not.** Ulirsch's thesis appears as the excluded `doi:10.7301/z0hq3x99` and again as an unidentified `\bibitem` whose printed text carries a typo ("Brown Univrsity") and no identifier. Merging records under every identifier does not help when one route produces no identifier at all.

**A version directory must be named against the work's home, not its key.** ACGS is homed under its arXiv id and keyed by its journal DOI, which first produced `works/arxiv/1709.09864/1709.09864/src`. The rule is now what the identifier adds to the home: `main` for the work itself, `v2` for a later version, `arxiv-1901.00001` for an artifact of another scheme.

**An arXiv id without a version number names "the latest".** The seed says `arxiv:1709.09864`, so that is the version recorded, though the bytes are of whatever version arXiv served. Results belong to versions, so M2 needs the real number: one API call per arXiv work during enrichment.

**arXiv throttles bulk e-print downloads, and the refusal is a 406.** A fetch of 15 sources was refused after one download; a single probe ten minutes later was still refused; twenty minutes later the same URL answered 200 to curl, to urllib with no headers, and to weft alike. So the refusal is neither a missing header nor a user-agent: it is rate. `Accept: */*` is worth sending (urllib sends none by default) but it is not the discriminator, and an earlier reading of loom's 2026-09-17 incident as a header problem was wrong — that hour was throttling too.

Measured afterwards: a fetch at **17 seconds between requests downloaded five sources and was then refused**, three in a row, which ended the run; every failing URL answered 200 to curl and to weft a minute later; the next runs downloaded five more, then one more. So the endpoint refuses in bursts and recovers in about a minute, and a corpus is filled by resuming rather than by waiting.

**That number is confounded, and the confounding is the lesson.** loom was fetching e-prints from the same machine while weft was, so arXiv saw roughly twice the rate either tool intended: a service throttles a client, and two processes are one client. Nothing about the count of five is a property of arXiv. What follows is the fix: the host budget now records its last request per host under `$WEFT_STATE_DIR`, else `~/.cache/weft/hosts/`, so two weft processes hold each other back; `WEFT_STATE_DIR=` empty turns sharing off, which is what the tests do. Any other tool that fetches from the same machine — loom's own `digest fetch` while it still has one — is outside that budget, so the rate must be re-measured with nothing else running before any number here is trusted.

Consequences, now in the code: bulk downloads take **15 seconds per host beyond the metadata spacing** (`download.BULK_SPACING`), a **406 is not retried** — asking again sooner only earns another — and the stop after three refusals in a row, ported from loom, ends the fetch and says to resume. For thousands of works this is the argument for arXiv's bulk access, which plan 0.1 §11 defers rather than pretends to solve. Worth knowing for anything that runs weft: **two weft processes do not share the budget**, so a plan and a fetch must not run at once. That is the same mistake, at the process level, that cost loom an hour.

## Still open at the end of M1

# M2 and M3 — statements out of LaTeX, and the edges a paper states

M2 reads a work's LaTeX into statements and proofs; M3 draws the edges §8.3 of [the digest contract](../specs/digest.md) allows and no others. Both are built, run on every corpus, and specified: `docs/specs/digest.md` is now normative for both implementations, and `tests/test_digest_contract.py` exercises its numbered statements.

## What is built

`weft extract` (amsthm counter emulation, `.aux` numbering where a compile left one, the macro block, `proofs: none|verbatim`), `weft link`, and the query surface over both: `weft get|closure|dependents|work|versions|search|serve`. A digest and a `results.json` per version, with the digest readable by loom and the JSON feeding the index. 178 tests; ruff and mypy clean.

## Measurements

**synthetic — a closed corpus.** 3 versions, 7 results, 7 proofs kept verbatim, then **4 internal edges, 3 by locator, 3 to a work with no locator, 0 unmatched, 0 ambiguous**. Every edge kind the contract allows appears, and the multi-part postnote `Theorems 1.1 and 2.3` resolves to two edges rather than one ambiguity.

**relloc — a real corpus.** 301 works crawled, **7 with a source fetched**, all 7 extracted: **413 results**. The linker then found **282 internal edges, 0 by locator, 13 to a work with no locator, 1 locator matching nothing**.

## Findings

**Cross-paper edges are unmeasurable at 2% coverage, and that is arithmetic rather than a bug.** An edge needs *both* ends extracted. relloc has 7 of 301 works extracted (2.3%); of the 240 citations inside its extracted statements and proofs, 48 carry a locator, 14 name a citekey the bibliography identified to a work, and **0 of those works have an extraction in this corpus**. The linker had zero opportunities, so zero is the only number it could report. The synthetic corpus, where every cited work is present, draws its 3 locator edges from the same code. What this measures is arXiv's throttling, not the linker: a corpus is only worth linking once a *neighbourhood* is closed, so the next fill should take one seed and every work it cites, rather than a broad shallow walk.

**Identifying a reference is not the same as having it.** 390 of relloc's 688 references are identified to a work and 217 carry a citekey, which is enough to key on; what is missing is the source. The cheap half of the pipeline runs far ahead of the expensive half, and the coverage number that matters is sources fetched, not works known.

**A service's polite refusal will be stored as data unless something checks its shape.** zbMATH answers a record whose licence forbids redistribution with the sentence "zbMATH Open Web Interface contents unavailable due to conflicting licenses." in *every* text field — title, author names, reference text, and the DOI. Taken at its word it produced `works/doi/zbMATH_Open_Web_Interface_contents_unavailable…/`, one phantom work that **four** restricted records had merged into, reached from four different papers and carrying their MSC codes. Two fixes, both at the boundary: `identity.is_doi` accepts only `10.<digits>/<no whitespace>`, so no sentence can become an identifier again, and `zbmath.shown` maps the notice to the empty string in every field, because absent is the truth — zbMATH declined to say. The phantom and the references naming it are cleaned out of both corpora; the HTTP cache still holds what the service actually said, which is correct.

**A reference with neither a citekey nor text is dropped on rebuild, and says so.** That is what a cleaned reference becomes, and the warning is the right shape: the index refuses to hold a row that names nothing.

# M4 — surfaces

One set of questions, three faces: `weft.query` for a caller who imports it, `weft serve` for anything that would rather ask over a socket, `weft mcp` for an agent. M4's acceptance test — *an agent, given only the MCP tools, can answer "what does this theorem depend on, and where is each dependency stated"* — is met, and is a test: `closure` with `text` answers it in one call, over the real stdio transport.

## What is built

`weft mcp`: MCP over JSON-RPC on stdio with no dependency beyond the standard library, eight read-only tools, and `dispatch` as a pure function of a request and a corpus so the protocol is tested without a subprocess. `view/`: a SvelteKit single-page app sharing arras's stack — search, a work with its versions and what it cites, a result with its statement, its proof, what uses it and a force-laid graph of what it rests on. 186 Python tests and 13 view units, plus two browser tests that build the app, serve `demos/synthetic`, and read it.

## Findings

**Reading the first page found a query bug that no test had.** A work's `cites` was built by cutting each edge target at its `#`, which for an internal edge leaves a *version* id: every paper appeared to cite itself, and a reader was offered a link to a version where a work belonged. Now resolved through a new `Store.version` and filtered to other works. The lesson is cheap and worth keeping: a payload nobody looks at is a payload nobody checks, and the view is the first thing that looked.

**A statement's citations are already resolved, so the view should not re-decide them.** The linker records the locator it matched as an edge's evidence, which is enough to turn `\cite[Theorem 1.1]{other}` in a proof into a link to the result it named — by lookup, not by a second parse of the postnote. A citation nothing resolved is shown as the paper printed it. The same rule as everywhere else in weft: what a paper states, or nothing.

**The seam a cross-origin view needs is one header.** `weft serve` now answers preflight and sends `Access-Control-Allow-Origin`, which is not a weakening: every route is read-only and answers the same to anyone who can already reach the port.

# The closed neighbourhood: ACGS and everything it cites

M3 said cross-paper edges were unmeasurable at 2% coverage and that the next fill should close one seed's neighbourhood rather than walk broad and shallow. This is that fill: `arxiv:1709.09864` and the 47 works it cites, at depth 2 with the cap raised to 60 and `math.SG` added to the categories — the seed is a Gromov-Witten paper, and symplectic geometry is its neighbour rather than another field.

**41 downloadable, 36 fetched, 35 extracted, 2347 results, 608 proofs.** Then 1606 internal edges and, after two bugs the closed corpus exposed, **8 edges by locator: the first cross-paper edges weft has drawn on real papers.**

## arXiv was not throttling. It was the host.

The fetch was refused at once: 406 on the first three e-prints, and the stop-after-three rule ended the run. This time the measurement was clean — nothing else on the machine was fetching — so the A/B was worth making, and it was decisive: **within the same minute, `curl` got 200 and Python's `urllib` got 406 on the same URLs**, with weft's headers, with curl's User-Agent, with no headers at all, with every `Accept-Encoding`, over HTTP/1.1 and HTTP/2 alike. A rate limiter does not distinguish two clients asking for the same file one second apart.

The fix is the host arXiv asks automated clients to use. `export.arxiv.org/e-print/...` answered **35 downloads in a row with no refusal at all**, where `arxiv.org/e-print/...` had refused after one. Both serve the same bytes and both are one host to the budget, so nothing about the spacing changed; only the name did.

This is the second correction to the same story. The 2026-09-17 hour of refusals was read as a missing header, then corrected to throttling; the throttling reading was itself confounded by loom fetching at the same time, and is now wrong too. What was measured all along was **which host the request went to**. The lesson is not about arXiv: three readings were argued from server behaviour alone, and only the A/B against a second client settled it. The rate budget stays — it is politeness, and correct on its own terms — but nothing in the earlier entries about arXiv's tolerance was a measurement of arXiv's tolerance.

## Two bugs that only a closed corpus could show

**A paper cites the preprint; the corpus files the work under its DOI.** The first link over the neighbourhood drew **0 locator edges from 322 citations carrying one**, with 131 naming a citekey the bibliography had identified. The linker compared identifier strings, and a citation naming `arxiv:0902.0087` never met the record keyed `doi:10.2140/gt.2019.23.1621`. Of 135 distinct cited works, **2 matched a record key directly and 26 more matched one of a record's other identifiers** — so 93% of what was resolvable was being thrown away by a string comparison. `_citekeys` now resolves every identifier a record carries to that record's key.

**Emulated numbering is not good enough for a locator.** With the identifier fix the neighbourhood drew 4 locator edges and 40 misses; the misses were `Proposition 1.5.6`, `Corollary 4.5.1`, `Theorem 5.3.3` — three-level numbers against papers weft had numbered `1.1`, `2.1`. The amsthm emulation does not follow `\numberwithin` or a shared counter declared indirectly, and one paper came out shifted by one within a section. `weft extract --all --compile` built **34 of 35 papers** and read their own `.aux`: locator edges went **4 → 8** and misses **40 → 36**. A corpus that wants locator edges compiles.

## What is left, measured rather than guessed

Of the locator parts aimed at a work the corpus actually holds: **18 in all, 8 matched, 10 missed.** The 10 are three cases and no fourth.

- **7 and 2 of them are the preprint reading of a published number.** The citing author writes `Definition 1.17` of the JAMS version while weft holds the arXiv version, whose Definition is 1.16; `Thm. 1.1.2` of the Compositio version while the preprint numbers by section. This is §8.1 of the digest contract arriving in the data: numbering is a property of the artifact, and a locator naming one artifact is wrong about the other. It is not fixable by better matching, only by holding the published version too — and the linker should say so rather than reporting "matched nothing", since a work held only as a preprint is a different failure from a locator nobody can place.
- **1 is `Section~3.1`.** Extraction writes sectioning units into the digest (`\label{<prefix>-sec-3.1}`) but does not record them in `results.json`, so nothing indexes them and a citation naming a section can never resolve. Whether a section should be a row beside the results is a design question, not a bug: a section has no statement, and an edge to one means "rests on the discussion in §3.1". Logged rather than decided, like the multi-match question.

The other number worth keeping: **322 citations carry a locator and only 18 aim at a work in the corpus**, because a depth-2 neighbourhood of one paper holds 47 works and those papers cite hundreds more. Closing a neighbourhood makes the edges measurable; it does not make them plentiful. A corpus that wants a dense graph needs the *citations' own* neighbourhoods, which is depth 3 and roughly twenty times the fetching.

# The spacing, measured at last

The 2026-09-17 entry above set `download.BULK_SPACING` to 15 seconds and reasoned about arXiv's tolerance from refusals. Both the reasoning and the number were consequences of the same mistake, and this closes it.

**35 e-print PDFs from `export.arxiv.org`, at arXiv's own stated rate of one request every three seconds: 35 downloaded, none refused, 102 seconds wall, 2.9 seconds a request, 22.9 MB.** The spacing is now 3.0. The fivefold penalty was bought with nothing: it was chosen to appease a rate limit that was never the problem, and it stayed in for a day after the host fix removed the problem, because nobody went back to re-measure a number that had stopped meaning anything.

The general lesson, which is the same one twice: **a mitigation outlives the diagnosis that justified it unless someone re-measures.** The first version of this record blamed a header, the second blamed a rate, the third found a hostname; only this fourth pass removed the cost the second one added. When a diagnosis is corrected, every setting it produced is suspect, and the cheapest thing to do is re-run the measurement that set it.

## What else this run settled

**The corpus now holds a page for every extracted work.** 35 PDFs, one per arXiv version of ACGS's neighbourhood: the artifact a crop is taken from, which the library's trustworthiness rests on. A PDF averages 0.65 MB against 0.22 MB for a compressed e-print, so both artifacts cost about 0.9 MB and six seconds a work.

**A PDF was already being produced and discarded.** `weft extract --compile` runs `latexmk -pdf` into a temporary directory, takes the `.aux` and deletes the rest, for 34 of 35 papers. It is not a substitute for the published artifact — page breaks differ, and a locator naming "p. 9" means the page its author saw — but it is a free fallback where a PDF cannot be fetched and a source can.
